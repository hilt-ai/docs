---
title: "End-to-end data flow"
description: "How events travel from the collector to the dashboard."
---

Events generated by the collector follow a simple pipeline from the host to the dashboard.

<Note>
The pipeline components described below reflect an **AWS deployment**. Other clouds use equivalent services — for example, AKS on Azure or ACK on Ali Cloud instead of ECS/EKS, and Event Hubs or Message Queue for Apache Kafka instead of MSK.
</Note>

<Steps>
  <Step title="Collector">
    Produces events and sends them in batches to the ingest endpoint.
  </Step>
  <Step title="Ingest service">
    The endpoint resolves via PrivateLink to an internal NLB fronting an ECS Fargate service in your VPC. Each event is published to Amazon MSK (Kafka) for buffering.
  </Step>
  <Step title="Enrichment">
    An EKS deployment consumes the MSK topic, enriches events, and writes normalized data into ClickHouse.
  </Step>
  <Step title="Classification">
    A dedicated classification workload scores events and evaluates model drift against historical data in ClickHouse.
  </Step>
  <Step title="Dashboard and query service">
    The dashboard (frontend, backend, and query service) runs on ECS Fargate behind an internal ALB, providing the investigation UI, API, and natural-language query interface.
  </Step>
</Steps>

For full infrastructure details, see the deployment guides: [AWS](/deployment/aws), [GCP](/deployment/gcp), [Azure](/deployment/azure), [Ali Cloud](/deployment/ali-cloud).
