The agent captures kernel-level telemetry (file access, process execution, network flows) via eBPF. On a busy host, raw syscall volume can exceed **100k events/second** the vast majority of which is OS housekeeping noise with low governance value. The filtering system reduces this to a manageable stream of security-relevant events through a two-tier architecture: **kernel-space** filters that drop events before they ever leave the eBPF ring buffer, and **userspace** filters that apply richer logic once events reach the agent process.

## Architecture overview

Events that survive both tiers are serialized to JSON and either written to disk or shipped to the collector.

## Tier 1: kernel-space filters

Kernel-space filters execute inside eBPF programs attached to syscall tracepoints. They run on **every** syscall invocation and must be fast, the payoff is that dropped events never consume ring buffer capacity or wake the userspace agent.

### Self-filter (`is_self`)

Every BPF program's first check. Compares the calling process's TGID against the agent's own PID (stored in `self_tgid_map` at startup). Without this, the agent's own file I/O and network traffic would create a feedback loop.

### Comm filter (`is_comm_filtered`)

Drops events from processes whose `comm` (task name, 16 bytes) matches a pre-populated BPF hash map. 

**Default filtered comms:**

| Process | Reason |
| :-- | :-- |
| `irqbalance` | IRQ distribution daemon — constant `/proc` reads |
| `gssproxy` | Kerberos / GSSAPI proxy — heavy socket \+ file I/O |
| `sleep` | Shell `sleep` builtin — zero security relevance |

This filter is applied to `openat`, `openat2`, `unlinkat`, `renameat2`, `fchmodat`, and `sched_process_fork` tracepoints. It is **not** applied to `sched_process_exec` (we always want to see what was executed) or `inet_sock_set_state` (runs in softirq context where `current->comm` is unreliable).

### Path prefix filter (`is_path_filtered`)

A fast, fixed-logic prefix matcher that drops read-only file opens on well-known noisy paths before they reach the ring buffer. It eliminates the majority of benign locale, library, and pseudo-filesystem reads.

**Filtered prefixes:**

| Prefix | What it catches |
| :-- | :-- |
| `/proc/` | procfs reads (per-PID stat, status, mountinfo) |
| `/dev/` | Device file access (null, tty, urandom) |
| `/sys/` | sysfs / cgroup controller reads |
| `/usr/lib/` | Shared library loads |
| `/usr/share/` | Locale data, shared assets |
| `/etc/l` | `ld.so.cache`, `localtime` |

**Write bypass:** For `openat`, if the flags include any write flag (`O_WRONLY | O_RDWR | O_CREAT | O_TRUNC | O_APPEND`), the path filter is skipped entirely. Writes to `/proc`, `/dev`, or `/sys` are always security-relevant.

## Tier 2: userspace filters

Userspace filters run when the agent polls events from the ring buffer. They have access to the full event struct and can perform operations (string matching, trie lookups, CIDR arithmetic) that are impossible or impractical in BPF.

### Self-filter (userspace)

Catches any events that leaked past the kernel self-filter (e.g., during the brief window between `main_bpf__attach()` and `self_tgid_map` population).

### Process comm filter (userspace)

Mirrors the kernel comm filter as a defense-in-depth backstop. Identical process list: `irqbalance`, `gssproxy`, `sleep`.

### Kubernetes infrastructure filter

On Kubernetes nodes, system components generate enormous file-open volume against non-sensitive paths. This filter drops read-only file opens from K8s infrastructure processes **unless** the path matches a sensitive-path allowlist.

**Filtered K8s comms:**

| Process | Role |
| :-- | :-- |
| `kubelet` | Node agent |
| `containerd-shim` | Container runtime shim |
| `eks-node-monito` | EKS node monitoring |
| `eks-healthchec` | EKS health checker |
| `eks-pod-identit` | EKS pod identity agent |
| `eks-ebs-csi-dri` | EKS EBS CSI driver |
| `coredns` | Cluster DNS |
| `systemd` | Init system |
| `systemctl` | systemd CLI |

**Sensitive path allowlist**, file opens from the above processes are **kept** if the path contains:

| Pattern | Why it matters |
| :-- | :-- |
| `token` | Service account tokens, API tokens |
| `ca.crt` | Certificate authority certificates |
| `secret` | Kubernetes secrets |
| `Corefile` | CoreDNS configuration |
| `resolv.conf` | DNS resolver config |
| `kubeconfig` | Kubernetes credentials |

If `comm` is a K8s infra process AND the file open has no write flags AND the path doesn't match the sensitive allowlist → filter. All writes from K8s infra processes are always passed through.

### Auxv noise filter

Drops `/proc/self/auxv` reads from `uptime` and `free` — these are benign ELF auxiliary vector reads that add no governance signal.

### Path filter trie (`path_filter_match`)

A userspace trie data structure for high-fidelity path matching with support for exact matches, prefix matches, suffix matches, and wildcards. It handles paths that passed the kernel filter but are still noise.

**Match modes:**

- **Exact** (`is_exact = 1`): the full path must match exactly.
- **Prefix** (`is_exact = 0`): any path that starts with the rule path matches.
- **Suffix** (`check_suffix = 1`): prefix match plus the full original path must contain the specified suffix string. 
- **Wildcard** (`*`): a `*` segment matches any single path segment. 

**Trie structure:**

```text
root
├── usr
│   ├── lib
│   │   ├── locale [prefix]
│   │   └── gconv [prefix]
│   └── share
│       ├── locale [prefix]
│       └── locale-langpack [prefix]
├── proc
│   ├── stat [exact]
│   ├── uptime [exact]
│   ├── * (wildcard)
│   │   ├── stat [exact]
│   │   ├── status [exact]
│   │   └── ...
│   └── ...
└── ...
```

Trie lookup is O(d) where d is the depth of the path (number of `/`-separated segments), with O(c) child search at each node where c ≤ 16 (`MAX_CHILDREN`).

## Filter bypass: cgroup lifecycle events

`CGROUP_MKDIR` and `CGROUP_RMDIR` events **bypass all filtering**, both kernel and userspace. These events are critical for maintaining the container identity cache and the `workload_by_cgroup_id` BPF map. Missing a cgroup creation event would leave all subsequent events from that container untagged.

## Metrics and observability

The agent tracks per-category filter counters and reports them on shutdown and every ~10 seconds to a metrics file:

| Metric | Description |
| :-- | :-- |
| `events_total` | Total events received from the ring buffer |
| `filtered_self` | Dropped because the event came from the agent itself |
| `filtered_comm` | Dropped by process name (kernel or userspace comm filter) |
| `filtered_path` | Dropped by path filter (kernel prefix or userspace trie) |
| `filtered_net` | Dropped by network CIDR filter |
| `passed` | Events that survived all filters and were output |
| `ringbuf_drops` | Events the kernel couldn't submit (ring buffer full) |

On shutdown, a summary is printed to stderr:

```text
--- Event Stats ---
Total: 482031, Filtered: 459218 (95.3%), Passed: 22813
  By self (agent): 1204, By process (userspace): 38201, By path: 419102, By net dest: 711
  Note: process-filtered events in kernel not counted above
```

## Configuration reference

| Variable | Default | Description |
| :-- | :-- | :-- |
| `DAG_EXCLUDE_NET_CIDRS` | _(none)_ | Comma-separated CIDRs to exclude from `NET_FLOW` events |
| `DAG_DISABLE_DEFAULT_LOCALHOST_FILTER` | `0` | Set to `1` to keep loopback and link-local traffic |

The comm filter and path filter rules are compiled into the agent binary and are not user-configurable at runtime.
