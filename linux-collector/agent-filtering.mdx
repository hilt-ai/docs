description: "How the collector reduces raw syscall volume to a security-relevant event stream."
---

The collector captures kernel-level telemetry (file access, process execution, network flows) via eBPF. On a busy host, raw syscall volume can exceed **100k events/second**, the vast majority of which is OS housekeeping noise with low governance value. The filtering system reduces this to a manageable stream of security-relevant events through a two-tier architecture.

## Architecture overview

| Tier | Where it runs | Purpose |
| :-- | :-- | :-- |
| **Kernel-space** | Inside eBPF programs on syscall tracepoints | Drops obvious noise before it ever leaves the ring buffer, at zero userspace cost |
| **Userspace** | In the collector process after ring buffer read | Applies richer logic (string matching, CIDR math) that isn't feasible in BPF |

Events that survive both tiers are serialized and either written to disk or shipped to the ingest endpoint.

---

## What gets filtered

The filtering pipeline removes events that have no governance or security value:

| Category | Examples | Why filtered |
| :-- | :-- | :-- |
| **Self-events** | The collector's own I/O | Prevents feedback loops |
| **OS housekeeping** | Locale loads, shared library opens, procfs reads | High volume, zero security signal |
| **Infrastructure noise** | Kubernetes node-agent file reads, systemd transient units | High volume from well-understood system components |
| **Loopback traffic** | localhost and link-local network connections | Internal-only, not governance-relevant (configurable) |

---

## What is never filtered

Certain event categories bypass all filtering regardless of source:

- **All process executions**: the collector always records what was executed, even from filtered processes
- **All write operations**: file writes to any path are always security-relevant
- **Container lifecycle events**: required for maintaining container identity mapping
- **Sensitive path access**: reads of credential files, tokens, secrets, and security-relevant configuration are preserved even from infrastructure processes

---

## Filtering behavior guarantees

| Guarantee | Detail |
| :-- | :-- |
| **Write-through** | Any file open with write flags always passes; writes are never filtered by path |
| **Exec-through** | Process execution events are never filtered by process name |
| **Defense in depth** | Kernel and userspace filters are layered; userspace re-checks as a backstop |
| **No content inspection** | Filters operate on metadata (path prefix, process name, CIDR), never on file or packet contents |

---

## Metrics and observability

The collector tracks filter hit rates and reports them periodically:

| Metric | Description |
| :-- | :-- |
| `events_total` | Total events received from the ring buffer |
| `filtered_self` | Dropped: event came from the collector itself |
| `filtered_comm` | Dropped: process name matched infrastructure filter |
| `filtered_path` | Dropped: path matched noise category |
| `filtered_net` | Dropped: destination matched excluded CIDR |
| `passed` | Events that survived all filters and were output |
| `ringbuf_drops` | Events the kernel couldn't submit (ring buffer full) |

On shutdown, a summary is printed:

```text
--- Event Stats ---
Total: 482031, Filtered: 459218 (95.3%), Passed: 22813
```

## Configuration

| Variable | Default | Description |
| :-- | :-- | :-- |
| `DAG_EXCLUDE_NET_CIDRS` | _(none)_ | Comma-separated CIDRs to exclude from network flow events |
| `DAG_DISABLE_DEFAULT_LOCALHOST_FILTER` | `0` | Set to `1` to keep loopback and link-local traffic |

The built-in noise filters are compiled into the collector and are not user-configurable. They target well-known system paths and infrastructure processes that generate high volume with no security signal.
