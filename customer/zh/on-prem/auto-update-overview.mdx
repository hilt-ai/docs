## 概览

自动更新代理是一个轻量级容器，以 Kubernetes CronJob 的形式部署在现有的 EKS 集群上。它会：

1. 轮询 Hilt 发布 ECR（`297433793776`），查找符合所配置版本策略的新镜像标签。
2. 将新镜像镜像到客户的 ECR 仓库。
3. 强制触发 ECS 服务重新部署以及 EKS 滚动重启。
4. 在滚动发布后验证健康状态。
5. 将状态上报到可配置的 webhook（Slack、电子邮件等）。

## 版本策略

发布标签采用 CalVer 格式 `vYEAR.MONTH.DAY`（例如 `v2026.04.27`）。该代理采用**基于前缀的补丁更新策略**：

| 当前标签 | 自动更新范围 | 匹配示例 |
| :-- | :-- | :-- |
| `v2026.04.27` | 相同的 `vYEAR.MONTH.*` 前缀 | `v2026.04.28`、`v2026.04.30` |
| `v2026.04.27` | 阻止 | `v2026.05.01`（下一个月） |
| `v2026.04.27` | 阻止 | `v2027.01.01`（下一年） |

该范围是可配置的。运维人员可以设置 `UPDATE_POLICY=patch`（默认值）、`UPDATE_POLICY=minor` 或 `UPDATE_POLICY=any`（任意更新的标签）。除非设置 `UPDATE_POLICY=any`，否则主版本号的跳跃式升级始终需要运维人员显式操作。
