## Hilt 监控什么以及如何决策

Hilt 不依赖签名或已知恶意列表。相反，两个互补的引擎协同工作来检测威胁：

**统计引擎**为每台主机构建滚动行为基线，跟踪进程执行模式、网络目的地、文件访问、数据流动以及数十种派生的行为信号。它使用针对计数数据、时间模式和关联特征优化的统计方法，对每个新观测值与基线进行评分。当行为偏离基线时，统计引擎会量化其异常程度。

**检测模型**基于你的环境行为数据进行训练，学习统计基线无法单独捕捉的更深层时间模式：看起来单独正常但集体异常的活动序列，或在多个观测窗口中逐渐显现的细微变化。模型独立地对每个 epoch 进行评分，并使用一种考虑信号之间依赖关系的组合方法，将其评估与统计引擎的输出相结合。

这两个引擎协同工作，捕捉的威胁范围比单独任何一个都要广。统计引擎快速且可解释；检测模型则为需要从数据中学习的模式增加了判断能力。当引擎判定某些行为足够异常值得调查时，一个**发现项**会出现在[异常](/zh/dashboard/anomalies)页面上。发现项来自 **ML 引擎和检测规则**。

### 观测内容

每隔五分钟，Hilt 的采集器将主机活动汇总为一个**行为快照**（一个 _epoch_）。每个 epoch 在以下维度捕捉数十个特征：

- **进程活动**：执行计数、唯一二进制文件、父子关系、会话行为、fork 模式
- **网络活动**：传输字节数、唯一目的地和端口、新连接、跨集群通信
- **文件活动**：访问模式、敏感文件交互、写操作、破坏性操作
- **数据流动**：关联的读取后发送模式、敏感数据外泄信号
- **时间结构**：基于小波的多时间尺度活动节律分析

这些原始特征与派生行为信号（熵度量、转换概率、新颖性评分和时间相关性）相结合，赋予每个 epoch 丰富的行为指纹，引擎据此与主机的历史记录进行评分。

### 冷启动期

由于 Hilt 需要先学习什么是正常的才能识别什么是异常的，新主机会经历一个**冷启动阶段**。基本评分在部署后数小时内开始，但随着基线在最初一到两周内逐渐完善，检测质量会不断提高。在此期间，评分阈值被提高以抑制噪音，因为系统仍在学习中。完整的部署时间线请参阅[快速入门](/zh/getting-started)。

## 严重性、置信度及其在发现项上的含义

[异常](/zh/dashboard/anomalies)页面上的每个发现项都附带三个评级，帮助你确定优先级：

### 严重性

**Critical**（严重）、**High**（高）、**Medium**（中）或 **Low**（低）。严重性反映异常在统计上的极端程度。一个 Critical 发现项代表在主机正常配置文件下极不可能发生的行为；一个 Low 发现项是可检测的偏差，但在某些环境中可能自然发生。严重性决定排序顺序，帮助你的团队首先关注最显著的异常。

### 置信度

**High**（高）、**Medium**（中）或 **Low**（低）。置信度反映检测模型中有多少独立评分通道一致认为该行为是异常的。高置信度意味着所有通道都独立标记了该 epoch；低置信度意味着只有一个通道触发。可以将其理解为佐证：高置信度的发现项有多个独立的理由认为该行为异常，而不仅仅是一个。

### 紧迫性

基于发现项中存在的证据类型的额外维度。紧迫性考虑涉及事件的性质，而不仅仅是其统计量级。紧迫性有助于区分证据类型本身令人担忧的发现项（新型横向移动、敏感文件访问）和主要由流量变化驱动的发现项。

这三个评级是独立的：一个发现项可以是高严重性但低置信度（单一信号上的大幅峰值），或中等严重性但高置信度（跨所有通道确认的适度偏差）。[异常](/zh/dashboard/anomalies)页面允许你按任意组合进行筛选和排序。

## 理解你的准确性指标

**Model Lifecycle** 页面（管理菜单下）跟踪三个指标，它们共同告诉你检测模型在你的环境中表现如何。每次评估新模型版本时，这些指标都会更新。

### 威胁捕获率

_"模型检测到了多少百分比的已知攻击场景？"_

Hilt 维护一个内部**基准测试套件**：一组精心策划的攻击场景，涵盖不同隐蔽程度的横向移动、权限提升、数据外泄和其他威胁类别。每次模型重新训练时，Hilt 都会回放此基准测试并衡量模型正确标记了多少场景。

该指标是模型相对于基准测试的**召回率**：`威胁捕获率 = 已标记的攻击场景 / 总攻击场景`。

更高的百分比意味着更广泛的覆盖。由于基准测试在模型版本之间保持可控和一致，此指标允许你直接比较版本。如果威胁捕获率上升，说明新模型捕获了旧模型遗漏的攻击。基准测试本身会随着新威胁类别的出现而更新，因此覆盖范围随威胁形势一同演进。

### 真实威胁保留率

_"模型更新时，是否仍能捕获你的团队已确认的威胁？"_

此指标来自你团队的**反馈**。当分析师确认某个发现项为真实威胁时，该确认会成为未来模型版本的测试用例。Hilt 会针对候选模型回放这些已确认的事件，检查新模型是否仍会标记它们。

`真实威胁保留率 = 仍被标记的已确认威胁 / 已确认威胁总数`

这可以防止回归：一个捕获新攻击类型但悄悄丢弃你已验证威胁的模型更新，会在此处显示下降。当指标尚不可用（反馈数据不足）时，UI 显示"—"（长破折号）。

### 你不会再看到的误报

_"新模型产生的噪音是否比旧模型少？"_

当分析师驳回一个发现项时，他们正在识别一个对其环境来说正常的模式。Hilt 会跟踪新模型版本是否仍会呈现那些相同的被驳回发现项——还是已经学会避免它们。

`避免的误报 = 不再产生的被驳回发现项 / 被驳回发现项总数`

这是一个**噪音降低率**，范围限于你的团队已审阅的模式。它与精确率（真阳性 / 所有警报）相关但范围更窄：精确率衡量所有发现项的质量，而此指标衡量分析师标记为误报的子集上的改进。数值上升意味着模型正在吸收你的反馈，在已知误报上产生更少的噪音。

与真实威胁保留率一样，当尚不可用时显示"—"（长破折号）。

### 模型裁决

在针对基准测试和你团队的反馈进行评估后，每个模型版本会获得一个裁决：

| 裁决 | 含义 |
| :-- | :-- |
| **"Your protection strengthened…"** | 新模型在一个或多个指标上有所改进，且未在其他指标上退步。自动升级。 |
| **"No change needed"** | 性能与上一版本相当。新模型被升级。 |
| **"We held this update back…"** | 新模型在一个或多个指标上出现退步。之前的模型保持活跃，Hilt 标记该问题以供审查。 |

模型在替换活跃模型之前必须通过多阶段评估。该评估包括上述基准回放和 HITL（人在回路中）回放，以及模型评分行为的内部一致性检查。未通过任何关卡的模型将被自动保留。

## Hilt 检测威胁的速度有多快

检测时间（TTD）衡量**Hilt 在异常行为开始后多快标记威胁**，以 epoch（五分钟窗口）为单位。Hilt 在模型评估期间将 TTD 衡量为攻击场景开始与第一个发现项之间的 epoch 数。

### 影响检测速度的因素

| 因素 | 对 TTD 的影响 |
| :-- | :-- |
| **基线成熟度** | 建立良好的基线（1-2 周的观测）可产生更快、更有置信度的检测。仍处于冷启动阶段的主机阈值较高，这可能会延迟标记，直到积累足够的行为历史。 |
| **攻击隐蔽性** | 大胆的偏差（横向移动爆发、出站数据峰值）会在第一个 epoch 被标记。隐蔽的低速攻击模式需要更长时间，因为检测模型需要观察多个 epoch，直到统计证据变得足够有说服力。 |
| **环境噪音** | 当你的团队驳回误报时，这些模式在未来的评分中会被抑制。更干净的信号意味着真实威胁在更少的背景噪音中更快地脱颖而出。 |
| **主机行为规律性** | 工作负载一致的主机具有更紧凑的基线，因此偏差检测更快。高度可变的主机（如具有突发工作负载的构建服务器）基线更宽，可能需要多一两个 epoch 才能跨过检测阈值。 |

### 预期结果

对于具有已建立基线的环境，内部基准测试中观察到的典型范围：

- **明显威胁**（大幅行为峰值、新型横向移动）：在 **1-2 个 epoch** 内检测到（5-10 分钟）
- **中等威胁**（异常网络目的地、非典型进程树）：在 **2-5 个 epoch** 内检测到（10-25 分钟）
- **隐蔽威胁**（缓慢数据外泄、渐进式权限提升）：在 **5-15 个 epoch** 内检测到（25-75 分钟），随着证据在多个观测窗口中积累

这些是来自受控评估场景的代表性范围，并非保证。实际 TTD 取决于上述因素和威胁的特征。检测模型会持续针对不同隐蔽程度的攻击场景进行评估，以确保这些范围在模型演进过程中保持有效。

## 检测能力如何随时间提升

Hilt 的准确性不是静态的。三种机制推动持续改进：

### 分析师反馈

你的团队审阅的每个发现项都会直接影响未来的检测质量——但确认和驳回的机制不同。

**被驳回的发现项**进入实时抑制层。当你的团队将一个发现项标记为误报时，Hilt 会构建该模式的行为指纹，并使用它来抑制类似的未来发现项。这种抑制是即时的（在几分钟内生效）且具有针对性。它针对的是你的分析师识别的模式，而不是广泛的行为类别。随着时间推移，这会清理你环境中特有的噪音，让真实威胁更清晰地浮出水面。

**被确认的发现项**成为测试用例。当评估新模型版本时，Hilt 会回放你确认的威胁并检查新模型是否仍能捕获它们。这就是"真实威胁保留率"指标的工作原理。你团队的确认成为每个未来模型必须通过的回归测试套件。

这就是为什么对发现项进行分流很重要：每次审阅要么消除一个特定的噪音来源，要么为真实威胁添加一个回归测试。

### 模型重新训练

Hilt 不按固定计划重新训练。当当前模型对你环境的拟合度下降时，数据驱动信号会触发重新训练：特征漂移、异常率变化或校准退化。最大间隔作为兜底机制，确保即使没有漂移信号触发，模型也能保持最新。

每个候选模型在替换活跃模型之前，都会经过多阶段评估，包括基准回放和你团队的反馈历史。如果在任何指标上出现退步，Hilt 会自动保留它。**Model Lifecycle** 页面显示完整的训练和评估历史，包括哪些模型被升级、哪些被保留以及原因。

### 基线自适应

统计引擎的基线是随着你的环境变化而演进的滚动窗口。它会逐渐纳入新的软件部署、基础设施变更和工作负载转移，因此不再将合法变更标记为异常。异常 epoch 被排除在这些更新之外，以防止攻击污染正常配置文件。如果基线被冻结太久，安全阀会强制更新，以防止误报螺旋无限期地锁定基线。

## 关键术语

| 术语 | 定义 |
| :-- | :-- |
| **Epoch** | 五分钟的主机活动窗口。行为观测和评分的基本单位。 |
| **基线** | 特定主机正常行为的滚动统计配置文件。在冷启动期间开始构建，并随着新的非异常数据到达而持续优化。 |
| **冷启动** | 系统学习基线的初始阶段（数小时到数天）。基本评分在数小时内开始；完整检测质量在 1-2 周内随着基线完善而发展。 |
| **发现项** | 由检测引擎标记的行为异常，或用户定义的检测规则的匹配项。出现在异常页面上供审阅。 |
| **基准测试套件** | 一组不同隐蔽程度的精心策划的攻击场景，用于衡量模型召回率。由 Hilt 控制，随着新威胁类别的出现而更新。 |
| **严重性** | 异常在统计上的极端程度（Critical、High、Medium、Low）。 |
| **置信度** | 有多少独立评分通道一致认为行为异常（High、Medium、Low）。 |
| **TTD** | 检测时间——异常行为开始到第一个发现项之间的 epoch 数。 |
