隔离是 Hilt 的网络隔离响应功能。当主机出现受损迹象或主动数据外泄时，可以将其隔离 — 切断网络访问以防止横向移动或持续数据丢失，同时保留调查能力。

---

## 隔离工作原理

当主机被隔离时：

1. **网络隔离**：主机的安全组（AWS）或等效网络策略被替换为隔离安全组，该组阻止所有入站和出站流量，仅保留 Hilt 采集器的摄取路径。
2. **采集器继续运行**：Hilt 采集器维持其出站连接，因此遥测数据继续流入以供取证分析。
3. **状态记录**：原始安全组 ID 被保存，以便操作可以回滚。
4. **审计追踪**：隔离操作和时间戳会被记录。

<Warning>
隔离会切断主机的网络连接。主机上运行的工作负载将失去连接。仅在继续运行的安全风险超过可用性影响时才使用隔离。
</Warning>

## 隔离页面

隔离页面提供全主机群范围的隔离状态视图。

### 概要条

页面顶部的三项指标：

- **Active quarantines**：当前被隔离的主机数量
- **Connections blocked**：被隔离主机上被阻止的连接尝试总数
- **Fleet hosts**：主机总数，用于提供上下文参考

### 主机列表

每台被隔离的主机显示为一行，包含：

- **状态徽章**：Isolated（正在被隔离）或 Pending review（已标记，等待隔离决策）
- **Host ID** 及识别信息
- **网络足迹**：该主机近期通信的摘要 — 已连接的内部主机、外部目的地和关键服务

### 主机群态势

Node Readiness 表格展示主机群的整体隔离态势：

- **Mode**：Observing（仅监控不执行）或 Enforcing（具备主动隔离能力）
- **Per-node readiness**：每台主机隔离资格的准确度和置信度指标

## 解除隔离

要将已隔离主机恢复正常运行：

1. 在隔离页面导航到被隔离的主机
2. 点击 **Unquarantine host**
3. 通过 **Yes, restore access** 确认

主机的原始安全组将被恢复，重新建立其先前的网络访问。

---

## 网络足迹

隔离后，仪表盘会为被隔离的主机显示一份网络足迹摘要：

- **Internal hosts reached**：该主机在隔离前 7 天内通信过的其他主机
- **External destinations**：该主机连接过的外部地址
- **Critical services**：依赖该主机或被该主机访问的关键服务

这有助于评估影响范围并确定后续调查的优先级。

## 限制

| 限制 | 详情 |
| :-- | :-- |
| **仅限云端** | 通过安全组进行隔离需要 AWS（或等效的云 API 访问）。当前不支持没有云安全组的本地 VM。 |
| **仅限网络层** | 隔离在网络层进行隔离。它不会终止进程、锁定账户或修改主机状态。 |
| **需要 IAM 权限** | Hilt 部署必须具有修改你账户中安全组的权限。 |
