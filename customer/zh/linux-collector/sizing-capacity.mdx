## 实测资源占用

| 主机类型 | RSS | CPU | 过滤掉的噪声 | 每秒发送事件数 |
| :-- | :-- | :-- | :-- | :-- |
| `m6i.large` 通用型 VM | 4–6 MB | \< 单核的 1% | ~60–75% | 50–400 |
| `r6i.xlarge` 数据库主机 | 6–8 MB | ~单核的 1% | ~70–80% | 300–1,500 |
| EKS 工作节点（16 个 Pod，繁忙） | 5–7 MB | \< 单核的 2% | ~70% | 800–3,000 |

## 默认值

采集器出厂时采用适用于大多数环境的保守默认值：

- **Kubernetes：** DaemonSet 请求 `100m` CPU / `128Mi` 内存，限制为 `500m` / `512Mi`。
- **VM：** 默认不施加硬性限制，但如需严格上限，可在安装期间强制设定（例如 `CPUQuota=20%` 与 `MemoryMax=512M`）。

## 环形缓冲区调优

默认的环形缓冲区大小为每 CPU 1 MB，足以应对每 CPU 最高约 5,000 事件/秒的工作负载。对于高吞吐系统，建议将其增大到每 CPU 8–16 MB。

代理在负载下会优雅降级：当用户态来不及足够快地排空环形缓冲区时，eBPF 侧会丢弃最早的事件，并向指标流（`metrics.c`）发送一个丢弃事件计数。被丢弃的事件绝不会导致代理阻塞内核。
