## 内核

Linux 内核 **4.18+**（RHEL/CentOS/Rocky 8、Ubuntu 20.04 或更新版本）。

- **5.8+** 且启用原生 BTF（`CONFIG_DEBUG_INFO_BTF=y`）：直接使用 `/sys/kernel/btf/vmlinux` —— 这是首选的 CO-RE 路径。
- **4.18–5.7**：发布 tarball 在 `btf/` 目录下包含捆绑的最小 BTF 文件；当原生 BTF 不存在时，代理会使用这些文件。

启动时代理会自动检测内核版本并选择 BPF 后端（**5.11+** 使用现代后端，**4.18–5.10** 使用传统后端）。同时支持 cgroup v1 和 v2。

<Note>
`openat2` 文件打开事件类型仅在内核 **5.6+** 上可用。在较旧的内核上，标准的 `openat` 事件类型覆盖所有文件打开操作 —— 检测覆盖范围等价，但事件类型不同。
</Note>

## 架构

`x86_64` 或 `aarch64`（Graviton）。每种架构各自交付一个 tarball；容器镜像则为多架构（multi-arch）。

## 特权

- **VM：** root
- **Kubernetes：** `privileged: true` 容器

## 出站网络

通过 AWS PrivateLink 向你的 `DAG_SHIP_URL` 发起 HTTPS（443）连接。

## 内存

生产环境实测：稳态下 4–6 MB RSS。

## CPU

在典型工作负载下\< 单核的 1%；环形缓冲区与用户态过滤可平滑峰值。

## 支持的发行版

统一代理支持生产环境中的每一个主流发行版：

- Amazon Linux 2（内核 5.10）和 Amazon Linux 2023
- Ubuntu 20.04\+（HWE）/ 22.04 / 24.04
- RHEL 8\+ / Rocky / Alma
- Debian 11\+
- Bottlerocket
- Flatcar
- EKS 优化版 AMI

优先使用带原生 BTF 的 **5.8+** 内核。**4.18–5.7** 内核依赖发布 tarball 中捆绑的 BTF —— 对于受支持的传统内核，无需单独安装 BTF 包。
