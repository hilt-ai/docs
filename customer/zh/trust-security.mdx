Hilt 是运行在您自有云账户中的 **数据移动治理（Data Movement Governance, DMG）** 平台。（该品类历史上常称为数据检测与响应，即 DDR。）您的遥测数据、分析数据库和仪表盘都位于 Hilt 在您账户中预配的基础设施内，Hilt 在运维平台时不持有对其的常驻访问权限。本节说明该模型如何保护您的数据，并为安全审查人员提供评估 Hilt 所需的细节，以应对供应商安全问卷。

---

## 信任原则

- **客户自有的基础设施与数据。** 每个部署都是单租户的，预配在您的云账户中（AWS、GCP、Azure 或阿里云）。遥测数据、分析存储和仪表盘均保留在您的账户内。
- **无隐蔽外泄。** 采集器遥测只有一个目的地：您账户中的摄取端点，通过私有网络访问。除匿名化导出管道外，没有任何数据离开您的账户；每次传输前您都会审核并批准。
- **最小权限、审批门控的访问。** Hilt 工程师不持有对您环境的常驻访问权限。访问仅通过您的审批流程进行，并被记录。
- **透明。** 采集器观测什么（以及绝不观测什么）均已记录在案，并在采集器内部强制执行，且仅限于元数据层面。
- **纵深防御。** 控制措施分层覆盖网络（私有子网、私有链路）、身份（基于角色的访问、团队范围限定）、加密（TLS 1.2+、静态 KMS）和应用（事件过滤、审计日志）。

---

## 架构速览

您主机上的采集器通过私有网络将元数据层面的遥测流式传输到您账户中的摄取端点。事件经过缓冲、富化、评分并存储到分析数据库，随后在仪表盘中呈现，全部都在您的云边界之内。离开您账户的唯一路径是匿名化导出管道——每项部署的核心组件，按日计划运行，且每次传输前需要您的批准。

有关组件构成、各云服务清单和数据流图，参见[架构与数据流](/zh/trust-security/architecture)。

## 控制措施汇总

| 控制领域 | 实现方式 | 责任方 |
| :-- | :-- | :-- |
| 部署模型 | 在您的云账户中单租户部署，使用 Terraform 预配 | Hilt 预配，您授予受限访问权限 |
| 网络隔离 | 私有子网、私有链路摄取、无公网入口 | 共担 |
| 传输加密 | 外部/摄取连接使用 TLS 1.2+；内部为私有网络 | Hilt |
| 静态加密 | 存储使用云提供商托管的加密（KMS / SSE） | Hilt 设计；密钥位于您账户的 KMS 中（CMK 可选） |
| 数据驻留 | 遥测数据保留在您的云账户中 | Hilt 设计，账户归您所有 |
| 身份与访问 | 仪表盘基于角色的访问，配合团队范围限定 | 您 |
| Hilt 工程师访问 | 审批门控、有时限、被记录、无常驻访问 | 共担 |
| 数据采集 | 仅元数据，不含文件内容或载荷 | Hilt 设计 |
| 数据导出 | 匿名化、传输前可审核 | 您（批准每次导出） |
| 响应控制 | 隔离与自定义检测规则 | 您 |

## 共享责任

Hilt 运维平台；您拥有平台所运行的云账户。责任划分如下。

| 领域 | 客户 | Hilt |
| :-- | :-- | :-- |
| 云账户安全 | 保护并监控账户、IAM 和组织护栏 | 仅在您授予的范围内运维 |
| 网络配置 | 按部署指南配置防火墙与路由 | 提供要求，预配私有摄取 |
| 采集器部署 | 部署与升级采集器（或启用自动更新） | 提供制品、指南和自动更新代理 |
| 平台基础设施 | 批准维护窗口 | 预配、修补、升级并监控平台组件 |
| 仪表盘用户管理 | 创建用户，分配角色与团队 | 提供基于角色的访问模型 |
| 加密密钥 | 默认由提供商托管；如需可提供 CMK | 在平台存储上启用提供商加密 |
| 数据导出审批 | 审核清单、批准或删除每次导出 | 提供管道与匿名化控制 |
| 事件响应 | 上报事件、处置发现项、隔离主机 | 调查平台问题并通知您 |
