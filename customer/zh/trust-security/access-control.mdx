对 Hilt 部署的访问在两个层面受到治理：您的用户向仪表盘认证，并受角色和团队约束；而 Hilt 工程师只能通过您的审批流程进入您的环境。两个层面均可审计。

---

## 仪表盘认证

仪表盘针对存储在部署仪表盘数据库中的账户进行认证（基于 PostgreSQL 的认证）。这里没有邮件邀请流程；管理员直接创建每个账户，设置用户名和临时密码（至少 8 个字符），用户在首次登录后将其替换。禁用账户会可逆地阻止登录；删除账户会移除该账户及其所有会话。

如需身份提供方集成选项，请联系您的 Hilt 代表。账户生命周期细节参见[用户管理](/zh/administration/user-management)。

## 角色与权限

每个用户持有一个角色。角色映射到固定的权限集：

| 角色 | 可执行的操作 |
| :-- | :-- |
| **Owner** | 与 admin 相同；固定绑定到初始账户，无法分配、更改或删除 |
| **Admin** | 完整访问权限，包括管理用户、团队和审计日志 |
| **Analyst** | 完整的数据访问和检测规则管理权限，无管理类页面 |
| **Responder** | 与 analyst 类似，但不能创建、编辑或删除检测规则 |
| **Viewer** | 只读访问权限，外加 AI 查询页面 |

敏感操作由特定权限把关，包括 *manage users*、*manage teams*、*manage alerts*、*manage rules* 和 *quarantine hosts*。完整角色参考参见[用户管理](/zh/administration/user-management)。

## 团队范围限定

团队约束用户可见的主机。一个团队拥有一组主机，其成员可见这些主机，而子团队被限制为其父团队主机的子集。

- **全局管理员**（未隶属任何团队的 admin 或 owner）可见所有内容。
- **受限管理员**是被分配到一个或多个团队的 admin，仅管理该子树。
- 在用户记录上设置的团队成员归属，决定了主机可见性。

基于团队的范围限定需要基于 PostgreSQL 的认证。参见[团队](/zh/administration/teams)。

## 审计日志

与安全相关的操作会被记录到由管理员管理的审计日志。记录的事件包括：

- 隔离与解除隔离操作，含发起操作的用户和时间戳（参见[隔离](/zh/dashboard/quarantine)）
- 匿名化导出事件，含导出 ID、行数、日期范围和审批状态（参见[匿名数据导出](/zh/on-prem/data-export-overview)）
- 用户账户变更；用户被删除后，审计历史仍以该用户名保留条目

由于审计日志位于您账户中的仪表盘数据库内，该记录始终在您的掌控之下。

## Hilt 工程师访问

Hilt 工程师不持有对您环境的常驻访问权限。

- **审批门控。** 仅通过在预配时建立的审批流程授予访问权限。
- **无常驻管理员。** 您的部署中不存在常驻的 Hilt 管理员账户。
- **被记录。** 通过您的流程授予的访问会被您云账户自身的日志记录。
- **受限且有时限。** 访问应限于具体任务并在之后撤销。具体的审批机制和时限在您的协议和预配运行手册中定义。

由于部署运行在您的账户中，您可随时使用云提供商的 IAM 控制撤销 Hilt 的访问。

<Note>
对于主机隔离等敏感操作，该操作通过您的仪表盘、由具备权限的用户执行，并记录在审计日志中。隔离要求部署持有在您账户中修改安全组的 IAM 权限，该权限在预配时授予。参见[隔离](/zh/dashboard/quarantine)。
</Note>
