本页面介绍从签约到看到第一个安全发现之间的流程。涵盖职责划分、部署时间线，以及平台学习你的环境期间的预期。

---

## 部署阶段

<Steps>
  <Step title="基础设施预配（第 1 天）">
    Hilt 在你的云账户（AWS、GCP、Azure 或阿里云）中预配单租户部署。包括分析数据库、仪表盘和摄取端点。

    **负责方：** Hilt 工程团队，由你的云管理员授予访问权限。

    **你需要提供：** VPC 或网络段、按部署指南的 IAM/服务账户权限，以及使用自定义子域名时的 DNS 委派。
  </Step>
  <Step title="采集器部署（第 1-3 天）">
    将 Hilt 采集器部署到你的主机。采集器是一个单独的静态二进制文件（Linux）或托管代理（macOS），无依赖、无内核模块。

    **负责方：** 你的基础设施团队，使用提供的指南：
    - [Kubernetes 部署](/zh/linux-collector/deploy-kubernetes)
    - [VM 部署](/zh/linux-collector/deploy-vms)
    - [ECS Fargate 部署](/zh/linux-collector/deploy-fargate)
    - [macOS 采集器](/zh/macos-collector/layout)

    **典型范围：** 先从覆盖主要工作负载类型的代表性子集（10–50 台主机）开始。基线建立后再扩展。
  </Step>
  <Step title="冷启动与基线（第 1-2 周）">
    检测模型开始学习你的环境的正常行为。在此阶段：

    - 遥测数据立即流入仪表盘，因此你从第一天起就可以浏览活动
    - 异常评分启动但以 **冷启动模式** 运行，阈值较高
    - 平台为每台主机和每个用户建立行为基线

    **预期：** 第一周很少或没有发现项。模型需要先观察正常模式，然后才能识别偏差，因此这是设计使然。
  </Step>
  <Step title="主动评分（第 3 周及以后）">
    基线稳定后，评分阈值降低，发现项开始出现。当你提供反馈（确认或驳回发现项）时，系统会持续优化。

    **预期：** 初始发现项会包含真正的异常和对你环境来说正常的模式。审阅这些（通过[异常](/zh/dashboard/anomalies)页面）会训练模型适应你的特定上下文。
  </Step>
</Steps>

## 职责划分

| 职责 | Hilt | 客户 |
| :-- | :-- | :-- |
| 预配云基础设施 | ✓ | 授予访问权限 |
| 部署采集器 | 支持与指南 | ✓ |
| 配置网络/防火墙规则 | 提供要求 | ✓ |
| 监控平台健康 | ✓ | |
| 审阅发现项并提供反馈 | | ✓ |
| 平台升级 | ✓ | 批准维护窗口 |
| 采集器升级 | 提供制品 | ✓（或使用自动更新） |

## 第一周检查清单

- [ ] 仪表盘可通过你的部署 URL 访问
- [ ] 至少一个采集器在上报（查看[采集器](/zh/dashboard/collectors)页面）
- [ ] 主机在主机群视图中显示为"存活"
- [ ] 事件在[调查](/zh/dashboard/investigate)中可见
- [ ] 你的团队拥有具有适当角色的仪表盘账户

## 实际时间线

| 里程碑 | 典型时间 |
| :-- | :-- |
| 首次遥测可见 | 采集器部署后数小时 |
| 全主机群部署完成 | 1–5 天（取决于主机群规模和部署方式） |
| 基线建立 | 1–2 周 |
| 首个有意义的发现项 | 2–3 周 |
| 模型完全校准 | 4–6 周 |

预热期因环境复杂度而异。工作负载高度规律的环境基线建立更快；多样或突发性的环境需要更长时间。
