## Overview

The auto-update agent is a lightweight container deployed as a Kubernetes CronJob on the existing EKS cluster. It:

1. Polls the Hilt release ECR (`297433793776`) for new image tags matching a configured version policy.
2. Mirrors new images to the customer's ECR repositories.
3. Forces ECS service redeployments and EKS rollout restarts.
4. Verifies health after rollout.
5. Reports status to a configurable webhook (Slack, email, etc.).

---

## Dashboard view

**Settings → System** provides a management panel for the auto-update agent:

- **Current version** — the active release tag (e.g., `v2026.04.28`).
- **Previous tag** — the release tag that was active before the last update.
- **Last updated** — the timestamp and actor (user or system) of the most recent update.
- **Automatic updates toggle** — an on/off switch to enable or disable automatic updates.

**Permissions**: viewing the dashboard panel requires the **`view_audit`** permission; toggling automatic updates on or off requires the **`manage_users`** permission.

<Note>
Disabling updates via the **dashboard toggle** keeps the CronJob scheduled but causes it to take no action on each run. This is different from disabling via Terraform (`auto_update_enabled = false`), which removes the CronJob entirely.
</Note>

## Operations reference

### Version policy

Release tags follow a CalVer format `vYEAR.MONTH.DAY` (e.g. `v2026.04.27`). The agent uses a **prefix-based patch update policy**:

| Current tag | Auto-update scope | Example match |
| :-- | :-- | :-- |
| `v2026.04.27` | Same `vYEAR.MONTH.*` prefix | `v2026.04.28`, `v2026.04.30` |
| `v2026.04.27` | Blocked | `v2026.05.01` (next month) |
| `v2026.04.27` | Blocked | `v2027.01.01` (next year) |

The scope is configurable. An operator can set `UPDATE_POLICY=patch` (default; same-month day updates), `UPDATE_POLICY=minor` (same-year month updates), or `UPDATE_POLICY=any` (any newer tag). Year (major) jumps always require explicit operator action unless `UPDATE_POLICY=any`. The Terraform variable `auto_update_policy` sets this container `UPDATE_POLICY` value.
