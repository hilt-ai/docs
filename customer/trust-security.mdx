Hilt is **Data Movement Governance (DMG)** that runs inside your own cloud account. (Historically this category was often called data detection and response, or DDR.) Your telemetry, the analytics database, and the dashboard live in infrastructure Hilt provisions in your account, and Hilt operates the platform without standing access to it. This section documents how that model protects your data and gives security reviewers the detail needed to evaluate Hilt against a vendor questionnaire.

---

## Trust principles

- **Customer-owned infrastructure and data.** Every deployment is single-tenant, provisioned in your cloud account (AWS, GCP, Azure, or Ali Cloud). Telemetry, the analytics store, and the dashboard stay in your account.
- **No covert egress.** Collector telemetry has one destination: the ingest endpoint in your account, reached over private networking. Nothing leaves your account except the anonymized export pipeline, which you review and approve before each transfer.
- **Least privilege, approval-gated access.** Hilt engineers hold no standing access to your environment. Access happens only through your approval workflow and is logged.
- **Transparency.** What the collector observes (and what it never observes) is documented and enforced in the collector itself, at the metadata level only.
- **Defense in depth.** Controls layer across network (private subnets, private link), identity (role-based access, team scoping), encryption (TLS 1.2+, KMS at rest), and application (event filtering, audit logging).

---

## Architecture at a glance

Collectors on your hosts stream metadata-level telemetry over private networking to an ingest endpoint in your account. Events are buffered, enriched, scored, and stored in an analytics database, then surfaced in a dashboard, all within your cloud boundary. The only path out of your account is the anonymized export pipeline, a core component of every deployment that runs on a daily schedule and requires your approval before each transfer.

For the component map, per-cloud service list, and a data-flow diagram, see [Architecture and data flow](/trust-security/architecture).

## Control summary

| Control area | Implementation | Responsibility |
| :-- | :-- | :-- |
| Deployment model | Single-tenant in your cloud account, provisioned with Terraform | Hilt provisions, you grant scoped access |
| Network isolation | Private subnets, private link ingest, no public ingress | Shared |
| Encryption in transit | TLS 1.2+ on all connections | Hilt |
| Encryption at rest | Cloud-native KMS encryption on all storage | Hilt (keys held in your account) |
| Data residency | Telemetry stays in your cloud account | Hilt design, you own the account |
| Identity and access | Dashboard role-based access with team scoping | You |
| Hilt engineer access | Approval-gated, time-bound, logged, no standing access | Shared |
| Data collection | Metadata only, no file contents or payloads | Hilt design |
| Data export | Anonymized, reviewable before transfer | You (approve each export) |
| Response controls | Quarantine and custom detection rules | You |

## Shared responsibility

Hilt operates the platform; you own the cloud account it runs in. Responsibilities split as follows.

| Area | Customer | Hilt |
| :-- | :-- | :-- |
| Cloud account security | Secure and monitor the account, IAM, and org guardrails | Operate only within the scope you grant |
| Network configuration | Configure firewall and routing per the deployment guide | Provide requirements, provision the private ingest |
| Collector deployment | Deploy and upgrade collectors (or enable auto-update) | Provide artifacts, guides, and the auto-update agent |
| Platform infrastructure | Approve maintenance windows | Provision, patch, upgrade, and monitor platform components |
| Dashboard user management | Create users, assign roles and teams | Provide the role-based access model |
| Encryption keys | Own the cloud KMS in your account | Configure KMS encryption on all platform storage |
| Data export approval | Review the manifest, approve or delete each export | Provide the pipeline and anonymization controls |
| Incident response | Report incidents, act on findings, quarantine hosts | Investigate platform issues and notify you |
