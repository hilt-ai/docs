The System Status page provides a real-time view of the health of every backend service powering your Hilt deployment. This page requires the **manage users** permission.

---

## Overall status

A banner at the top shows the aggregate health across all components:

| Status | Meaning |
| --- | --- |
| **All systems operational** | Every monitored component is healthy |
| **N service(s) need(s) attention** | One or more components are experiencing issues but the system is functional |
| **Some services disabled** | One or more components have been intentionally disabled |
| **No services monitored** | No backend components are reporting status |

---

## Component cards

Each backend component has a status card showing:

- **Component name** (e.g., Anomaly Narratives, TRACE Anomaly Detection, Event Enrichment, Backend Process, ClickHouse, Postgres).
- **Current status**: Operational, Degraded, Disabled, or No data.
- **Uptime history**: a 90-day visual history showing availability over time.

Component cards can also display **remediation steps** when a service is unhealthy, and a **backend vitals strip** with additional detail such as response times, queue depths, or resource usage.

### Infrastructure components

Infrastructure-level components (ClickHouse, Postgres) use an expandable card with a per-signal breakdown — individual health metrics like query latency, connection pool usage, and replication lag.

---

## Refreshing

The page auto-refreshes status data periodically. You can also click the **Refresh** button to force an immediate check. The header shows when the status was last checked.
