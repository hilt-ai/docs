The macOS collector embeds an on-device detection engine that evaluates kernel events as they happen. This section describes what that engine looks for and how findings reach the console.

For raw telemetry, see [Event coverage](/macos-collector/event-coverage). For console hubs that display related activity, see [Malware](/dashboard/malware), [Credentials](/dashboard/credentials), [Files](/dashboard/files), [Networks](/dashboard/networks), and [Frameworks](/dashboard/frameworks).

---

## Where detection happens

Detection runs **on the endpoint, inside ESensor**, before events leave the Mac. Because the engine sits on Apple's Endpoint Security AUTH path, it can **deny an operation in-kernel** rather than only report it afterward. Every evaluated event carries code-signing trust and application attribution — rules grade *who is acting*, not only *what happened*.

## How the agent responds

| Status | Meaning |
| --- | --- |
| `blocked` | Denied in-kernel (e.g. agent self-protection, clear Gatekeeper tamper) |
| `alerted` | Operation completed; elevated finding for review |
| `logged` | Recorded for context and correlation |

Severity scales with the actor's code-signing verdict. The collector protects its own app bundle and extensions — unauthorized kill/delete/rename attempts are denied in-kernel and surfaced as blocked tamper findings. Authorized MDM removal paths remain allowed; see [Uninstall](/macos-collector/uninstall).

---

## Shared finding layout

Findings typically include: **What happened · Process responsible · What was touched · Why it matters · Evidence · Recommended action**, plus severity/status and the responsible app's trust verdict.

---

## Kernel foundation (why macOS rows look different)

Every Endpoint Security event can carry:

- **Code-signing identity** — platform, Developer ID, ad hoc, unsigned/invalid
- **Application attribution** — owning app, not only `comm`

That is why persistence and tamper severity can be driven by *who* acted. Details: [Event data model](/macos-collector/event-data-model).

## From finding to dashboard

Findings use the same authenticated ingest path as telemetry. Triage them in [Malware](/dashboard/malware), map coverage in [Frameworks](/dashboard/frameworks), and deep-dive evidence in [Investigate](/dashboard/investigate) (macOS scope).
