Hilt runs as a single-tenant platform inside your own GCP project. A managed GKE cluster hosts the analytics engine (ClickHouse) and the dashboard, collectors on your hosts stream telemetry through a private Private Service Connect ingest endpoint into Pub/Sub, and all traffic stays inside your project with no public internet exposure.

---

## Services

| Service | Role |
| :-- | :-- |
| GKE | Managed Kubernetes for platform services, including the in-cluster ClickHouse analytics database |
| Pub/Sub | Event streaming |
| Private Service Connect | Private ingest endpoint |
| Cloud Storage | Long-term storage and data exports |
| Cloud SQL (PostgreSQL) | Dashboard database |
| Certificate Manager | TLS certificates |

---

## Network topology

- Collectors connect via a **Private Service Connect** endpoint
- VPC-native networking with no public IPs on platform pods
- Uses Workload Identity for GCP service authentication
- Outbound internet access only where needed for image pulls (configurable to use private registries)

---

## Provisioning

Hilt provisions your GCP deployment using Terraform. The typical process:

1. You provide a target GCP project with the agreed IAM permissions
2. Hilt applies the Terraform configuration to create all infrastructure (GKE, Pub/Sub, Cloud SQL, Cloud Storage, Private Service Connect, and networking)
3. Private Service Connect connectivity is established between your workload VPCs and the platform VPC
4. Collectors are deployed to your hosts using the [Linux](/linux-collector/layout) and [macOS](/macos-collector/layout) collector guides
