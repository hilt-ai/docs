Hilt deploys as a single-tenant platform inside your own cloud account. The architecture is consistent across providers: a managed Kubernetes cluster runs the analytics and dashboard services, with collectors deployed to your workload hosts.

---

## Supported clouds

| Cloud | Status | Key services used |
| :-- | :-- | :-- |
| **AWS** | Generally available | EKS, MSK, PrivateLink, S3, RDS |
| **GCP** | Generally available | GKE, Pub/Sub, Private Service Connect, Cloud Storage, Cloud SQL |
| **Azure** | Generally available | AKS, Event Hubs, Private Link, Blob Storage, Azure Database for PostgreSQL |
| **Ali Cloud** | Generally available | ACK, Message Queue for Kafka, PrivateLink, OSS, ApsaraDB RDS |

## Common architecture

Regardless of cloud provider, every Hilt deployment includes:

```
┌─────────────────────────────────────────────────────────┐
│  Your Cloud Account                                      │
│                                                          │
│  ┌──────────┐    ┌──────────────────────────────────┐   │
│  │ Collector │───▶│  Ingest Endpoint (Private Link)  │   │
│  │ (hosts)  │    └──────────────┬───────────────────┘   │
│  └──────────┘                   │                        │
│                                 ▼                        │
│                    ┌────────────────────────┐            │
│                    │  Streaming Platform     │            │
│                    │  (Kafka / Pub/Sub /     │            │
│                    │   Event Hubs / MQ)      │            │
│                    └───────────┬────────────┘            │
│                                │                         │
│                    ┌───────────▼────────────┐            │
│                    │  Analytics Engine       │            │
│                    │  (ClickHouse on K8s)    │            │
│                    └───────────┬────────────┘            │
│                                │                         │
│                    ┌───────────▼────────────┐            │
│                    │  Dashboard + API        │            │
│                    │  (PostgreSQL + Web)     │            │
│                    └────────────────────────┘            │
└─────────────────────────────────────────────────────────┘
```

### Components

| Component | Purpose |
| :-- | :-- |
| **Collectors** | eBPF-based agents on your workload hosts (Linux) or Endpoint Security agents (macOS) |
| **Ingest endpoint** | Private, encrypted endpoint that receives telemetry, with no public internet exposure |
| **Streaming platform** | Buffers and distributes events for processing |
| **Analytics engine** | ClickHouse cluster for telemetry storage, querying, and anomaly scoring |
| **Dashboard** | Web application with PostgreSQL backing store for user accounts, teams, and review state |

## AWS

### Services

| Service | Role |
| :-- | :-- |
| EKS | Managed Kubernetes for platform services |
| MSK (Kafka) | Event streaming |
| PrivateLink | Private ingest endpoint: collectors connect without traversing public internet |
| S3 | Long-term storage and data exports |
| RDS (PostgreSQL) | Dashboard database |
| ACM + Route 53 | TLS certificates and private DNS |

### Network topology

- Collectors connect to a **VPC Endpoint** (PrivateLink) in your account
- All traffic stays within AWS private networking
- No inbound internet access to any platform component
- Outbound internet access only where needed for image pulls (configurable to use private registries)

## GCP

### Services

| Service | Role |
| :-- | :-- |
| GKE | Managed Kubernetes for platform services |
| Pub/Sub | Event streaming |
| Private Service Connect | Private ingest endpoint |
| Cloud Storage | Long-term storage and data exports |
| Cloud SQL (PostgreSQL) | Dashboard database |
| Certificate Manager | TLS certificates |

### Network topology

- Collectors connect via **Private Service Connect** endpoint
- VPC-native networking with no public IPs on platform pods
- Uses Workload Identity for GCP service authentication

## Azure

### Services

| Service | Role |
| :-- | :-- |
| AKS | Managed Kubernetes for platform services |
| Event Hubs | Event streaming (Kafka-compatible) |
| Private Link | Private ingest endpoint |
| Blob Storage | Long-term storage and data exports |
| Azure Database for PostgreSQL | Dashboard database |
| App Gateway / Front Door | TLS termination (private only) |

### Network topology

- Collectors connect via **Azure Private Link** endpoint
- Platform runs in a private VNet with no public ingress
- Uses Managed Identity for Azure service authentication

## Ali Cloud

### Services

| Service | Role |
| :-- | :-- |
| ACK | Managed Kubernetes for platform services |
| Message Queue for Apache Kafka | Event streaming |
| PrivateLink | Private ingest endpoint |
| OSS | Long-term storage and data exports |
| ApsaraDB RDS (PostgreSQL) | Dashboard database |

### Network topology

- Collectors connect via **PrivateLink** endpoint within your VPC
- Platform deployed in a dedicated VSwitch with security group isolation
- RAM roles for service-to-service authentication

## Provisioning

Hilt provisions your deployment using Terraform. The typical provisioning process:

1. You provide a target cloud account/project/subscription with agreed IAM permissions
2. Hilt applies the Terraform configuration to create all infrastructure
3. Networking (PrivateLink/PSC/Private Link) is established between your workload VPCs and the platform VPC
4. Collectors are deployed to your hosts using the guides in this documentation

The full process is covered in [Getting Started](/getting-started).

## Security boundaries

| Boundary | Implementation |
| :-- | :-- |
| **Network isolation** | All components in private subnets; ingest via private link only |
| **Encryption in transit** | TLS 1.2+ on all connections |
| **Encryption at rest** | Cloud-native encryption (KMS-managed keys) on all storage |
| **Access control** | Hilt engineer access via your approval workflow only |
| **No data egress** | Telemetry never leaves your cloud account (except opt-in anonymized exports) |
