The macOS collector extends Hilt's data detection and response coverage to macOS endpoints, complementing the Linux collector that covers server infrastructure. Together they provide visibility across your full environment, from cloud servers to employee workstations.

---

## What it covers

| Surface | Technology | What it observes |
| :-- | :-- | :-- |
| **System activity** | Apple Endpoint Security framework | Process execution, file operations, network connections, the same event categories as the Linux collector |
| **Browser activity** | Managed Chrome extension | Web navigation patterns and download activity relevant to data movement governance |

---

## Architecture

The macOS collector consists of two components:

### System extension

A macOS system extension using Apple's Endpoint Security (ES) framework. It observes:

- Process creation and termination
- File opens, writes, renames, and deletes
- Network connection establishment and data transfer

The system extension runs as a user-space daemon with ES entitlements; no kernel extension (kext) required.

### Chrome extension (managed)

A managed Chrome extension deployed via MDM that observes:

- Navigation to external services
- File download events
- Upload activity to cloud storage and file-sharing services

The extension operates in read-only mode and does not modify, block, or inject into browser activity.

---

## Deployment

The macOS collector is deployed through your MDM (Mobile Device Management) solution:

1. **System extension**: distributed as a signed `.pkg` installer, approved via MDM profile for Endpoint Security entitlements
2. **Chrome extension**: force-installed via Chrome enterprise policy through MDM
3. **Configuration**: ingest endpoint and node identity configured via MDM preferences or a configuration profile

### Requirements

| Requirement | Detail |
| :-- | :-- |
| **macOS version** | 13.0 (Ventura) or later |
| **MDM** | Required for system extension approval and Chrome extension deployment |
| **Network** | Outbound HTTPS to your Hilt ingest endpoint |
| **Chrome** | Managed Chrome required for browser visibility (optional component) |

---

## What the macOS collector does not do

Consistent with the Linux collector's design philosophy:

- **Does not read file contents**: only metadata (path, operation type, size)
- **Does not capture keystrokes or screen content**
- **Does not block or modify activity**: strictly observational
- **Does not require Full Disk Access**: operates within Endpoint Security framework permissions
- **Does not capture packet payloads**: only connection metadata and byte counts

---

## Data flow

Telemetry from macOS endpoints flows through the same pipeline as Linux collector data:

1. Events observed by system extension / Chrome extension
2. Local buffering and noise filtering
3. Shipped to your Hilt ingest endpoint over HTTPS
4. Available in the same dashboard views (Investigate, Networks, Files, Users, Anomalies)

macOS hosts appear in the [Collectors](/dashboard/collectors) fleet view alongside Linux hosts, with a **macOS** host-type badge.

## Current limitations (early access)

| Limitation | Status |
| :-- | :-- |
| Auto-update | Not yet available: upgrades via MDM package push |
| Quarantine response | Not yet supported on macOS (AWS security-group isolation is Linux/cloud only) |
| Behavioral baselining | Supported, but model warm-up may take longer on highly variable workstation patterns |
| Self-managed deployment | MDM-only during early access |
