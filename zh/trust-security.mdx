## 架构原则

| 原则 | 实现方式 |
| :-- | :-- |
| **单租户，部署在你的云中** | 每位客户在自己的 AWS/GCP/Azure/阿里云账户中获得一个专属部署。Hilt 工程师仅通过你的审批流程进行访问。 |
| **仅元数据遥测** | 采集器捕获进程执行元数据、网络流摘要和文件操作事件。它**不会**读取文件内容、数据包载荷、内存或环境变量。 |
| **无横向网络访问** | 采集器仅向你的摄取端点（`DAG_SHIP_URL`）发起单个出站 HTTPS 连接。它不开放任何监听端口，无法从网络寻址。 |
| **最小权限** | 在 Kubernetes 上，采集器以特权 DaemonSet 运行，仅用于 eBPF 访问，它不会挂载 `/sys/kernel/btf` 之外的宿主文件系统。在 VM 上，它需要 `CAP_BPF` + `CAP_PERFMON`（或等效的 `LimitMEMLOCK`）。 |

## 数据处理

### 采集器能看到的

- 进程执行事件（命令、父进程、PID、UID、时间戳）
- 文件操作元数据（路径、打开标志、重命名前后，**不是**文件内容）
- 网络流摘要（源/目标 IP+端口、传输字节数、协议，**不是**数据包载荷）

### 采集器无法看到的

- 文件内容或应用层数据
- 数据包载荷或 HTTP 正文
- 环境变量、密钥或内存数据
- 剪贴板、屏幕或键盘输入

### 数据驻留

所有遥测数据都留在你的云账户内。分析数据库（ClickHouse）和仪表盘数据库（PostgreSQL）运行在你部署的 VPC 内。Hilt 不会在外部复制或镜像客户数据。

### 匿名化模型训练导出

对于选择加入的客户，结构化导出管道会生成匿名化特征向量用于模型改进。导出内容：

- 已去除所有标识符、文件路径、IP 和命令行
- 在传输前需经客户审阅和明确批准
- 详细文档见 [数据导出概述](/zh/on-prem/data-export-overview)

## 特权代理常见问题

**问：为什么采集器需要 root / 特权模式？**

eBPF 程序加载需要提升的权限（`CAP_BPF` + `CAP_PERFMON`，或在 Kubernetes 上以特权模式运行）。这是挂载 tracepoint 所需的最低权限，采集器不会将这些权限用于任何其他目的。

**问：采集器能否修改或阻止主机上的活动？**

不能。采集器严格只做观测。它挂载只读 tracepoint，从不修改系统调用行为、丢弃数据包或改变主机状态。隔离操作（如已配置）由控制面通过云 API（例如 AWS 安全组）执行，而非由采集器执行。

**问：采集器消耗多少资源？**

典型开销为 <2% CPU 和 <200 MB 内存。可通过 systemd cgroups 或 Kubernetes 资源请求/限制来强制执行资源限额。详见 [容量规划](/zh/linux-collector/sizing-capacity)。

**问：支持哪些内核版本？**

采集器需要启用 BTF（BPF Type Format）的 Linux 内核 5.8+。详见 [系统要求](/zh/linux-collector/system-requirements) 获取完整兼容矩阵。
