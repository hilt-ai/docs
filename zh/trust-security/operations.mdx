Hilt 运维您账户中的平台组件：发布版本、应用更新并监控平台健康。本页介绍这些发布背后的供应链及其相关的运维控制。

---

## 软件供应链

采集器版本以受 Hilt 控制的存储中的版本化制品形式分发：

- **发布制品。** 每个采集器版本以静态 Linux 压缩包（每种架构一个，`aarch64` 和 `x86_64`）外加一个匹配的多架构容器镜像形式发布，置于 Hilt 发布存储的版本化路径下。参见[发布制品](/zh/linux-collector/release-artifacts)。
- **静态二进制。** Linux 采集器是单个静态二进制文件，无运行时依赖、无内核模块，这降低了您主机上的依赖面。
- **隔离网络包。** 对于隔离网络环境，离线包附带完整制品集以及一个经 `docker save` 导出的镜像，因此运行时不会拉取任何内容。参见[网络与安全](/zh/linux-collector/networking-security)。
- **macOS 打包。** macOS 系统扩展以经签名的 `.pkg` 安装包形式分发，通过您的 MDM 批准，托管 Chrome 扩展通过企业策略强制安装。参见 [macOS 采集器](/zh/macos-collector)。

发布标签遵循 `vMAJOR.MINOR.PATCH`。如需对下载制品进行校验和或签名验证，请联系您的 Hilt 代表。

## 更新与修补

| 组件 | 更新方式 |
| :-- | :-- |
| **平台组件** | Hilt 预配并升级平台基础设施；您批准维护窗口 |
| **采集器（Linux）** | 您升级采集器，或启用自动更新代理进行推送 |
| **采集器（macOS）** | 通过您的 MDM 推送升级 |

可选的自动更新代理以 Kubernetes CronJob 的形式运行在您的集群中。它轮询 Hilt 发布仓库，将新镜像镜像到您自己的仓库，推出更新，在推出后验证健康，并向您配置的 Webhook 上报状态。其范围由版本策略治理（默认为 `patch`，或 `minor` / `any`）；除非您选择 `any`，否则主版本跳跃需要操作员显式介入。参见[自动更新代理](/zh/on-prem/auto-update-overview)。

## 监控

Hilt 监控其所运维平台组件的健康（责任划分参见[快速入门](/zh/getting-started)）。当自动更新代理应用更新时，它会在每次推出后验证平台健康，并将结果上报到您配置的 Webhook，从而使更新失败能够及时显现。

---

## 备份与灾难恢复

平台状态保存在托管云服务中（仪表盘数据库、分析数据库和对象存储），它们在您的账户中提供原生备份能力。恢复目标（RPO 与 RTO）取决于您的云配置和协议。请向您的 Hilt 代表确认您部署的备份计划和恢复目标。

## 日志

| 日志来源 | 存放位置 |
| :-- | :-- |
| 平台与基础设施日志 | 您云账户的原生日志 |
| 仪表盘审计日志 | 您账户中的仪表盘数据库（参见[访问与身份](/zh/trust-security/access-control)） |
| 采集器过滤与事件统计 | 由采集器上报（参见[采集器过滤](/zh/linux-collector/agent-filtering)） |

由于日志位于您的账户中，您可设定其保留期，并可将其接入现有的 SIEM 或日志管道。

---

## 变更管理

平台升级遵循上述版本化发布流程，并在您批准的维护窗口内运行。自动更新代理的版本策略让您明确控制哪些变更自动应用、哪些需要操作员介入，因此没有任何重大变更会在您一方未做决定的情况下抵达平台。参见[自动更新工作流](/zh/on-prem/auto-update-workflow)。
