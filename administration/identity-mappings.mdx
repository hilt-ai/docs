The Identity Mapping page connects the machine-level identities the Hilt collector observes (Linux usernames, Teleport sessions, PPID chains) to corporate accounts in your Okta directory. This helps you understand which person is behind activity on a host. This page requires the **manage users** permission.

---

## How it works

Hilt observes identity signals on your hosts — Linux login usernames, Teleport session identifiers, PPID chain patterns — and proposes mappings to Okta user accounts. You review, confirm, or reject these proposed mappings.

---

## Okta sync

A status bar at the top shows:

- **Sync status**: whether the last Okta directory sync succeeded or failed.
- **Last synced**: how long ago the directory was refreshed.
- **Okta users**: the total number of user accounts imported from Okta.

Use the **Sync now** button to trigger an immediate directory refresh.

---

## Mapping table

Each row in the mapping table shows:

| Column | Description |
| --- | --- |
| **Machine identity** | The identity observed on the host (e.g., a Linux username) |
| **Source** | Where the identity was observed (Linux username, Teleport session, PPID chain) |
| **Okta user** | The corporate account the identity is mapped to |
| **Status** | Proposed (awaiting review), Confirmed, or Rejected |
| **Type** | Automatic (proposed by Hilt) or Manual (created by an admin) |

---

## Reviewing mappings

For proposed mappings:

- **Confirm** — accepts the mapping, linking the machine identity to the Okta account.
- **Reject** — dismisses the mapping. Hilt will not propose the same pairing again.

You can also change a mapping's type between automatic and manual, or delete it entirely.

---

## Creating manual mappings

Click **New mapping** to manually link a machine identity to an Okta user. This is useful when the automatic matching can't resolve an identity — for example, when a Linux username differs significantly from the Okta email prefix.

---

## Statistics

A summary card shows mapping coverage:

- **Total identities** observed across your fleet.
- **Mapped** — identities successfully linked to Okta accounts.
- **Unmapped** — identities without a corporate account association.
- **Pending** — proposed mappings awaiting review.

---

## Filtering

Use the search bar to filter by machine identity or Okta username. A status filter lets you view all mappings or only those in a specific state (proposed, confirmed, rejected).
